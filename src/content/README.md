# Editorial content

Published content currently lives as structured plain-text paragraphs in `src/data/updates.json` and entity JSON. This avoids executing MDX or untrusted HTML. `guides/` and `updates/` may hold internal editorial Markdown in future; they are not automatically rendered or trusted. Only the validated JSON publishing path generates pages.

## Walkthrough acceptance standard

The owner requires guides that a new player can follow, not objective summaries. Before publishing or expanding a guide, check: the correct game/mode entry; the named location or visible landmark; the action and observed button/control when available; counters or other success cues; and the separate badge, hub credit and avatar-item claim. Link the actual game and relevant timestamped creator demonstrations where verified. For puzzles, stating “solve the puzzle” is not a solution: explain the observed mechanic and identify any missing sequence or variable layout. Label incomplete route knowledge instead of inventing turns or controls. Never invent mobile equivalents from keyboard controls.

Codes require the exact string, intended experience, source/check date, reward, entry location, redemption steps and evidence of validity. Distinguish source-reported codes from account-tested ones. If no event code or input flow is verified, state the scope of the check and provide a concrete reward-earning alternative. Do not copy reroll/EXP codes from the unrelated game HOLLOW.
